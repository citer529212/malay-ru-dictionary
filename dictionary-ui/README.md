# Малайско-русский и русско-малайский электронный словарь

Автономное веб-приложение с двунаправленным поиском. Пользователь сразу вводит
русское или малайское слово, после чего приложение автоматически определяет
направление, предлагает варианты и показывает проверенный перевод.

Разработчики: Чернобаев Б.Д. и Михина А.А.

Словарная база составлена на основе:

- «Большого малайско-русского словаря» Т.В. Дорофеевой, Е.С. Кукушкиной,
  В.А. Погадаева;
- «Русско-малайзийского словаря» В.А. Погадаева, Н.В. Ротт.

## Локальный запуск

```bash
cd "dictionary-ui"
python3 -m http.server 8080
```

Откройте [http://localhost:8080](http://localhost:8080). Загружать дополнительные
файлы не требуется: обе базы входят в приложение.

## Один HTML для работы без интернета

Стабильную переносимую версию можно собрать одной командой:

```bash
node dictionary-ui/tools/build_offline_html.mjs
```

В каталоге `Dictionary-Offline-HTML` появятся две версии. Full включает полную
базу с максимальным охватом. Lite сохраняет все gold- и специализированные статьи,
но ограничивает низкоприоритетный OCR-хвост и быстрее запускается на слабых
ноутбуках. Обе версии открываются двойным щелчком в современном браузере Windows,
macOS или Linux и не требуют интернета либо локального сервера. Рядом создаются
компактные ZIP-пакеты, инструкция `README.txt`, паспорта состава и контрольные
суммы SHA-256.

## Проверенная база (рекомендуется)

Файл `dictionary-ui/data/dictionary_curated.json` имеет самый высокий приоритет.
Если он существует, интерфейс работает в режиме только проверенных статей
(без OCR-фрагментов в выдаче).

Чтобы улучшать качество, добавляйте/правьте записи именно в
`dictionary_curated.json`.

Перед публикацией запустите контроль точных переводов и целостности gold-базы:

```bash

```

Проверка останавливается с ошибкой, если пропал эталонный перевод, появился
дубликат или грязная OCR-запись получила возможность заменить проверенную статью.

## Pipeline v2 (рекомендуется для качества)

Новый конвейер строит структурированную базу и сразу считает качество.

### 1) Подготовить sidecar-тексты

Для каждого OCR-PDF нужен TXT sidecar (разделитель страниц `\f`).

### 2) Запустить сборку

```bash
cd "dictionary-ui"
python3 ./tools/build_dictionary_pipeline_v2.py \
  --ms-ru-sidecar "/ABS/PATH/malay_ru_sidecar.txt" \
  --ru-ms-sidecar "/ABS/PATH/russian_malay_sidecar.txt" \
  --output-dir "./data" \
  --report "./data/dictionary_pipeline_report.json"
```

Или сразу от OCR-PDF (без ручного sidecar):

```bash
cd "dictionary-ui"
python3 ./tools/build_dictionary_pipeline_v2.py \
  --ms-ru-pdf "/ABS/PATH/malay_ru_ocr.pdf" \
  --ru-ms-pdf "/ABS/PATH/russian_malay_ocr.pdf" \
  --output-dir "./data" \
  --report "./data/dictionary_pipeline_report.json"
```

### 3) Что получится

- `data/dictionary_curated.json` (малайско-русский)
- `data/dictionary_ru_ms_curated.json` (русско-малайский)
- `data/dictionary_pipeline_report.json` (метрики)

В отчёте будут:
- число кандидатов
- число принятых/отбракованных
- итоговый размер базы
- покрытие контрольного набора частых слов

### 4) Как повышать качество дальше

1. Поднимать качество OCR страниц с плохим сканом и пересобирать.
2. Добавлять в `dictionary_ru_ms_gold.json` частотные слова, которых нет в OCR.
3. Повторять сборку и смотреть прирост `coverage_pct` в отчёте.


## Автономный контекстный корпус — этапы 1–16

800 двунаправленных выражений и 1350 параллельных учебных примеров находятся в
`data/context-corpus.js`. Переводы взяты из существующих verified gold-статей;
каждая запись хранит исходный ID, файл и исходную пару. Прежние базы не изменены.
Примеры составлены для корпуса: это учебные предложения, а не цитаты из публикаций.
Reverso и его данные не использовались.

Русские варианты включают согласованные падежные формы словосочетания.
У малайских именных выражений нет падежного изменения: в `forms.ms` сохранена
неизменяемая форма. Производные слова и перестановки не объявляются эквивалентами.

Поиск автоматически выбирает направление. Приоритет: точная проверенная фраза,
явная словоформа, самое длинное выражение внутри запроса, затем прочие словарные
и OCR-совпадения. Совпадение определяется по границам слов. В параллельном примере
выражение подсвечивается на обоих языках, включая склонённую русскую форму.

Проверки корпуса входят в существующую команду публикационного QA:

```bash
node dictionary-ui/tools/qa_dictionary_search.mjs
# Только корпус:
node dictionary-ui/tools/qa_context_corpus.mjs
# Автономные Full/Lite в отдельный каталог:
node dictionary-ui/tools/build_offline_html.mjs /tmp/dictionary-context-offline
```

Фиксированный набор `tools/context-fixtures.json` содержит 500 пар для каждого
направления. Дополнительно проверяются все 800 пар, словоформы, контекстные запросы,
приоритет и границы совпадений, безопасная подсветка и SHA-256 восьми прежних баз.
Паспорт источников и границы проверки: `CONTEXT_CORPUS.md`.

Браузерный QA требует установленного Playwright и Chromium, локального сервера
на `127.0.0.1:8097` и предварительно собранных Full/Lite:

```bash
node dictionary-ui/tools/qa_context_browser.mjs
```

При внешней установке Playwright задайте `CONTEXT_PLAYWRIGHT_MODULE` (абсолютный
путь к `playwright/index.mjs`) и при необходимости `CONTEXT_CHROMIUM_PATH`.
`CONTEXT_QA_URL`, `CONTEXT_OFFLINE_DIR` и `CONTEXT_QA_OUTPUT` позволяют выбрать
сервер, каталог автономных сборок и каталог скриншотов.

### Улучшения четвёртого этапа

Каталог открывается без запроса: выберите «Только с примерами» и при желании тему.
Доступны все 500 выражений и 700 примеров, в обоих направлениях. Список выводится
порциями по 24 записи: кнопка «Показать ещё» раскрывает следующую порцию, а счётчик
показывает видимую часть и полный объём. Каталог не обрезается до 300 записей;
раскрытые источники сохраняются при добавлении следующей порции.

Кнопка «Сохранить выражение» добавляет запись в личную подборку. Режим
«Сохранённые» поддерживает поиск и фильтр тем. Подборка сохраняется в локальном
хранилище браузера и доступна после перезагрузки, в том числе в автономном HTML.
Хранилище зависит от браузера и адреса запуска: сайт и отдельные HTML-файлы могут
иметь разные подборки. Синхронизация между устройствами не выполняется.

Кнопка «Скачать подборку JSON» выгружает выбранные выражения с исходными
переводами, формами, всеми примерами и происхождением. Это самостоятельный файл
данных, который можно восстановить через «Восстановить из JSON». При отказе локального
хранилища интерфейс сообщает об ошибке и не показывает запись сохранённой.

На этом этапе новые выражения и примеры не добавлялись: корпус и прежние базы
остались побайтно прежними, изменены функции работы с ними.

### Улучшения пятого этапа

«Восстановить из JSON» открывает файл, ранее выгруженный через «Скачать подборку
JSON». Перед добавлением отображаются число новых и уже сохранённых выражений,
а при наличии — дубликаты и отклонённые записи. Предварительный просмотр показывает
до пяти исходных пар и сообщает, сколько осталось. Кнопка «Добавить» объединяет
подборки; «Отмена» не меняет сохранённые данные.

Восстанавливаются только ID текущих verified-записей с совпадающими русской и
малайской парой и ID исходной статьи. Переводы, формы и примеры из файла не
заменяют содержимое корпуса. Неизвестные ID и несовпадающие пары пропускаются.
Повторное восстановление того же файла не создаёт дубликатов.

Поддерживается экспортный формат schemaVersion 1, размер до 2 МБ и не более
2 000 записей в файле. Чтение и восстановление выполняются локально, в том числе
в автономных Full/Lite. Если браузер отклоняет запись в хранилище, прежняя подборка
сохраняется, а предварительный просмотр остаётся доступен для повторной попытки.

Также исправлен сброс загруженной порции результатов отложенным поиском:
явный поиск, смена режима и другие действия отменяют ожидающий таймер ввода.
